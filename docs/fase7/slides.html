Parte 1 · Trigger de auditoria

Mudar um limiar de aviso deixa rastro

Baixar a régua de adesão de 80% para 60% muda quem recebe aviso. TRG_REGRA_ALERTA_AUDITORIA grava o antes e o depois de toda mudança em REGRA_ALERTA, venha da API, de um script ou do SQL Developer.

AFTER INSERT OR UPDATE OR DELETE ON regra_alerta
FOR EACH ROW
INSERT INTO regra_alerta_hist (codigo, operacao,
       limiar_antes, limiar_depois, ...)
VALUES (:NEW.codigo, v_operacao,
        :OLD.limiar, :NEW.limiar, ...);

Saída real: a régua baixada para 75% e devolvida para 80%

OperaçãoAntesDepoisProgramaQuando
UPDATE8075SQL*Plus04/11 20:49
UPDATE7580SQL*Plus04/11 20:49

De propósito, ela não engole erro

Se a auditoria falhar, a mudança no limiar falha junto. Mudar uma régua sem rastro não pode acontecer.

Parte 1 · Trigger de automação

A dose que deixa o remédio acabando vira aviso na mesma hora

  • TRG_MEDICACAO_ESTOQUE_BAIXO calcula por quantos dias o estoque ainda cobre a rotina, antes e depois de cada dose ou mudança de horário.
  • Só na travessia: quando a cobertura cai para 3 dias ou menos. As doses seguintes não repetem o aviso.
  • Sem tabela mutante: lê só :OLD e :NEW; a conta fica em PKG_MEDICACAO.
  • A dose vale mais que o aviso: se gravar o aviso falhar, a falha vai para o log e a dose fica. Um teste prova isso com a tabela de avisos travada.
  • O limiar mora em REGRA_ALERTA: auditado pela outra trigger e desligável sem deploy.
  • A dose pode chegar pela conversa: o agente de voz (IA generativa) ouve "tomei a levodopa", confirma pela API e a trigger avisa.

Parte 2 · Entrega contínua

Do push ao deploy com Oracle, sem passo manual

Job 1
build-e-testes

Java 21 + Maven. Build e suíte inteira: H2, PostgreSQL e Oracle reais em contêiner (Testcontainers).

→
Job 2
imagem

Imagem Docker da API publicada no GitHub Container Registry, marcada com o SHA do commit.

→
Job 3
deploy

Oracle efêmero + a imagem publicada. O Flyway cria tabelas, packages e triggers; PL/SQL conferido no banco; smoke pela API.

Logs

Artefato logs-deploy: API, Oracle, conferência do PL/SQL e smoke.

Relatórios

Resumo de cada run: testes por classe, migrations, objetos PL/SQL e a tabela do smoke.

Gatilho

Push na main ou manual. Em pull request roda só os testes: nada é publicado a partir de um PR.
